## Мультираздачи и неверный title_id (02.11.2026)

Отзыв: в менеджере почти у всех игр «НЕТ ДАННЫХ». Причина в данных каталога: у раздачи один `title_id`, и скрапер брал первый ID из текста темы.
- Мультираздача записана под одной игрой: Coffee Talk / Episode 2 / Tokyo — под Tokyo, Pokémon Sword / Shield — под Shield, Risk of Rain / Returns / 2 — под первой частью. Остальные игры по ID не находятся.
- В теме одиночной раздачи бывает ID другого региона: Rhythm Heaven Groove (`0100107027310000` вместо `0100D9F01D474000`), Castlevania Belmont's Curse, Once Upon a Katamari.
- Версия раздачи одна на всю мультираздачу (Coffee Talk 1.47, а у Episode 2 своя).

Исправление в трёх репозиториях:
- `switch-games` (скрапер): ID берётся из имён файлов раздачи; новое поле `titles` — все игры раздачи со своим обновлением `[vN]` и версией. `enrich_versions.py --titles` заполняет его у всей базы и исправляет `title_id`.
- `switch-game-collection` (сборщики каталогов): `titles` переносится в каталоги строкой `"ID:обновление:версия;…"`. Не массивом: SAX-парсер 2.20 и раньше на конце вложенного массива (кроме `screenshots`) считает законченным весь список игр.
- Приложение: `Game::titles`, кэш каталога версии 7. Раздача индексируется под каждой своей игрой (`catalog::releaseAppIds`), версия берётся для конкретной игры (`catalog::titleVersion`): менеджер, плитка, карточка (бейдж «установлена» для любой игры раздачи), выбор раздачи. Предупреждение при выборе файлов — только для одиночных раздач. Известное обновление 0 («в раздаче только база») даёт «Актуально», а не «Нет данных».
- Проверено на ПК: тест `test_game_version` (сценарии мультираздачи), каталог с `titles` разбирается и сохраняется в кэш v7 без расхождений с JSON (7267 раздач), загрузка из кэша. Экран менеджера на ПК глазами не проверен; на консоли не проверено.
- Чтобы заработало у пользователей: прогнать `enrich_versions.py --titles --push` на VPS, пересобрать каталоги. Приложение получит полный каталог при смене версии или через 48 ч.

## Что сейчас

Менеджер игр (`source/ui/LibraryView.cpp`, `scanForUpdates`) берёт «последнюю версию» не из каталога, а из двух внешних баз (`source/catalog/titledb.*`):
- `versions.txt` из 16BitWonder/nx-versions (~3 МБ) — номер последнего патча от Nintendo (`N << 16`);
- `versions.json` из blawar/titledb (~1,7 МБ) — даты обновлений и список игр без патчей.

Отсюда проблемы:
- **Статус «Доступно обновление» не значит, что его можно скачать.** Nintendo выпустила патч №5, а в каталоге раздача с №3 — игра висит в «Доступных обновлениях», «Обновить все» её пропускает и пишет «не удалось».
- **Показываем номер патча вместо версии.** В колонке «последняя» — «обн. 5 · 12.09.2026», а не «1.0.5»: из `N << 16` строку версии не получить.
- **Перед открытием менеджера ждём сеть.** `titledb::ensureDownloaded()` блокирует скан; без интернета менеджер пишет «не удалось загрузить titledb».
- **Карточка игры и менеджер считают по-разному.** Карточка (`GameDetailView::applyInstalledState`) сравнивает с версией раздачи, менеджер — с titledb. Одна и та же игра может быть «Обновить до 1.0.5» в карточке и «Актуальна» в менеджере, и наоборот.
- Плитка «Менеджер игр» на главном экране (`MainMenu.cpp`, ~строка 460) считает обновления ещё одним, третьим способом: сама разбирает `versions.txt`.
- Предупреждение «в раздаче старое обновление» при выборе файлов (`FileSelectView.cpp`, `checkReleaseUpdate`) тоже сравнивает с titledb.

## Что есть в каталоге

RU-каталог на 01.11.2026: 7271 запись, у 6955 есть `title_id`. Из них:
- `version` («1.0.3») — у 6857 (98 %);
- `update_version` (номер патча `N << 16`) — у 5206 (75 %);
- у 91 игры несколько раздач, версии в них разные (например `1.0` и `1.0.3`).

Мусор, который надо отсекать: 203 версии не в виде «1.2.3» — даты (`09.09.2026`), хэши сборок (`RC1 1d12337`), `NES: 9.1.0 / SNES: 6.0.0`. Буквенные суффиксы (`1.0.3b`) уже понимает `compareDotted`. Есть записи с `title_id` `0100000000000000` (хоумбрю-заглушка) — их нельзя склеивать в одну «игру».

## Новая логика

Источник правды — каталог. «Доступно обновление» значит: **в каталоге есть раздача этой игры с версией новее установленной**. Такое обновление всегда можно скачать.

Правило сравнения одно для всех экранов (то же, что в карточке сейчас):
1. Есть строка версии и у раздачи, и у установленной игры (NACP `display_version`) — сравниваем строки.
2. Иначе сравниваем номер патча раздачи `update_version` с установленным патчем.
3. Иначе — «версия неизвестна».

Установленная версия: NACP `display_version` из кэша скана (учитывает установленный патч) + «обн. N», если патч есть.

## Этапы

### Этап 1. Общий модуль версий

Новый `source/catalog/game_version.{h,cpp}` (без зависимостей от UI, чтобы собирался в pctest):
- `trimVersion`, `compareDotted` — перенести из `GameDetailView.cpp`.
- `isPlausibleVersion(s)` — отсекает даты, хэши, составные строки (первый компонент ≥ 1000, больше одного пробела, двоеточие и т. п.). Неправдоподобная версия считается неизвестной.
- `compareToInstalled(const Game& release, displayVer, patchVer)` → `Newer / Same / Older / Unknown` по правилу выше.
- `releaseVersionText(const Game&)` — перенести из карточки, использовать и в менеджере, и в `ReleaseChooser`.
- `newestRelease(releases)` — раздача с самой новой версией; при равенстве — порядок из `rankReleasesOf` (сиды, дата).

`GameDetailView` переходит на этот модуль, поведение карточки не меняется.

Тест `pctest/test_game_version.cpp`: сравнения, суффиксы, мусорные строки, случаи «строки нет — сравниваем патчи».

### Этап 2. Индекс версий по каталогу

`catalog::CatalogVersionIndex`: app ID → все раздачи и самая новая из них. Строится один раз на снимок каталога (кэш по указателю `getCatalogSnapshot()`), пересобирается после обновления каталога или диффа. Запись `0100000000000000` и прочие заглушки не индексируются.

`LibraryView::scanForUpdates` сейчас сам строит такой индекс (`CatalogIndex::byTid`) — он переезжает в общий класс, поиск по названию остаётся в менеджере.

### Этап 3. Менеджер игр

- Убрать из `scanForUpdates` загрузку и разбор titledb: скан начинается сразу и работает без сети.
- Статус по `compareToInstalled` с самой новой раздачей:
  - `Newer` → «Доступно обновление», в колонке справа «1.0.5» (или «1.0.5 (обн. 5)»);
  - `Same` / `Older` → «Актуальна»;
  - `Unknown` или игры нет в каталоге → «Другие игры», справа «—».
- Игры, найденные **только по названию** (нет совпадения по title ID), статус обновления не получают: версия может быть от другой игры. Раздачу открыть можно, как сейчас.
- `LibraryItem`: вместо `latestPatchVersion` хранить `latestVersion`/`latestPatch` самой новой раздачи и её индекс в `releases`. «Открыть раздачу» и «Обновить» ведут на неё, а не на первую по сидам.
- Каталог ещё не загружен при открытии менеджера → подпись «Каталог загружается…», после загрузки — пересчёт статусов без повторного опроса ncm (кэш скана уже есть).
- Подписи колонок/разделов: «Установлено» / «В каталоге», раздел «Обновления в каталоге — N». Переводы на 10 языков, `pctest/check_i18n.py`.

### Этап 4. «Обновить все»

`updateAllGames` (`LibraryView.cpp`, ~строка 1020): перебирать раздачи по убыванию версии, пропуская те, где `compareToInstalled != Newer`. Поиск файла патча в раздаче (`probeTorrentFiles` + `parseVersionFromFileName`) остаётся: каталог говорит, что раздача новее, а какой файл качать — видно только по списку файлов. Если в раздаче нет отдельного патча (полная сборка), сейчас игра попадает в «не удалось» — оставить так, но в итоговом списке писать причину «в раздаче нет отдельного обновления».

### Этап 5. Плитка на главном экране и выбор файлов

- `MainMenu.cpp`: счётчик обновлений через тот же индекс и кэш скана менеджера (там есть `display_version`), без разбора `versions.txt`. Число на плитке совпадёт с разделом менеджера.
- `FileSelectView::checkReleaseUpdate`: предупреждать, если **в каталоге есть другая раздача новее этой** (а не «Nintendo выпустила новее»), и предлагать её, как сейчас.

### Этап 6. Уборка titledb

Когда этапы 3–5 проверены на консоли:
- удалить `titledb::ensureDownloaded`, `latestVersions`, `knownGame`, `updateDate`, файлы `versions.txt`/`versions.json` и строку «База версий (titledb)» в хранилище (`StorageTabView.cpp`, `MainMenu.cpp` — подсчёт размера кэша), миграцию пути в `GameData.hpp`;
- оставить `updateOrdinal` (нужен для «обн. N») — перенести в `game_version.h`;
- удалить ключи `loading_titledb`, `titledb_failed`, `cache_versions`, `update_label_date` и `pctest/test_titledb.cpp`;
- старые файлы на SD удалить один раз при запуске.
