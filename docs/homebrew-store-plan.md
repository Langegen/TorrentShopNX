Буквы манифеста — сверено с исходниками libget (`src/Manifest.cpp`, `src/Package.cpp`), так же сделано в `planInstall` / `planRemoval`:

| Буква | Установка и обновление | Удаление |
|-------|------------------------|----------|
| `U` | пишется всегда | удаляется |
| `E` | пишется всегда | **остаётся** |
| `G` | пишется, только если файла нет (настройки) | удаляется (у нас: остаётся, если пользователь выбрал «Оставить настройки») |
| `L` | в архиве нет, создаёт программа | удаляется |

При обновлении файлы `U` старой версии, которых нет в новом манифесте, удаляются. Установлен = есть `manifest.install`; версия — поле `version` в `info.json`; манифест без `info.json` = «есть обновление». Размеры `filesize` / `extracted` в `repo.json` — в КиБ. `sha256` есть у 191 пакета из 512, у остальных проверяем `md5`. В архиве fortheusers рядом с файлами лежат `manifest.install` и `info.json`.

### Почему одного fortheusers мало

Проверено 09.11.2026:

- из 512 пакетов за последний год обновлялись только **169**;
- из 20 известных программ нет 11: sys-patch, Fizeau, ovl-sysmodules, nxdumptool, sys-con, NX Activity Log, TinWoo, Cyberfoil, AIO Switch Updater, Daybreak, Hekate Toolbox;
- свежие программы выходят на GitHub: по меткам `switch-homebrew`, `nintendo-switch-homebrew`, `libnx`, `tesla-overlay` около 300 проектов, обновлённых за последний год (без учёта тех, у кого меток нет);
- список GameBrew (gamebrew.org, «List of Switch homebrew applications») — больше 300 программ с датами обновлений, вики-таблица со ссылками на страницы программ.

### Второй источник: свой индекс, который собирается на сервере

Консоль не ходит в GitHub API: без входа там 60 запросов в час (поиск — 10 в минуту), на всех пользователей не хватит. Индекс собирает GitHub Action в `Langegen/switch-game-collection` (с `GITHUB_TOKEN`: 5000 запросов в час) раз в 6 ч и кладёт один файл `homebrew.json`. Консоль скачивает его с ETag, как `port_recipes.json`.

Что делает сборщик:

1. **Ручной список** `homebrew-sources.json`: репозиторий GitHub, какой файл релиза брать, категория, куда ставить (если не очевидно), зависимости, короткое описание на русском. Сюда — всё, чего нет или что устарело в fortheusers (Ultrahand и свежий nx-ovlloader вместо Tesla-menu 2023 года).
2. **Поиск новых**: по меткам GitHub и по ссылкам из списка GameBrew находит репозитории, в последнем релизе которых есть `.nro`, `.ovl` или zip с ними.
3. **Разбор релиза**: скачивает файл, считает `sha256`, составляет список файлов (для zip — оглавление). Из NRO и OVL берёт встроенные иконку, название, автора и версию (секция ASET и NACP), поэтому карточка будет с иконкой даже без ручной работы.
4. **Проверка путей** по тем же правилам, что и на консоли (раздел ниже). Пакет с запрещённым путём в индекс не попадает.
5. **Выход** `homebrew.json`: те же поля, что у `repo.json`, плюс `source: "github"`, `download_url`, `sha256`, `files` (готовый список файлов), `depends`, `repo` (`owner/name`).

На консоли два источника сливаются в один список:

- один и тот же проект узнаём по ссылке на GitHub (`url` в `repo.json`) или по пути к NRO;
- если версия на GitHub новее, ставится она; учёт в `switch/appstore/.get` общий для обоих источников;
- в `homebrew.json` же лежат **скрытые** пакеты (опасные, мёртвые, дубли наших эмуляторов: Tico, Vita3K, Cemu остаются в менеджере эмуляторов) и **зависимости** оверлеев (у fortheusers такого поля нет).

Если какой-то источник недоступен, работает кэш на карте (`data/homebrew/`) с пометкой «данные от <дата>».

Daybreak (обновление прошивки) — в список скрытых: он меняет системное ПО.

## Безопасность путей

Пакет пишет в корень SD. Список файлов проверяем до скачивания (`checkInstallPath`; таблица-тест — `pctest/homebrew_fixtures/path_rules.txt`, её же проверяет сборщик). «Предупреждение» значит: со сборщика такой пакет попадает в магазин только через ручной список; на консоли ставится.

| Путь | Правило |
|------|---------|
| `switch/`, `config/`, `themes/`, `roms/` и прочие папки данных | разрешено |
| `switch/.overlays/` | разрешено (оверлеи) |
| `atmosphere/contents/<tid>/` | разрешено, пакет помечается «системный модуль» |
| `atmosphere/contents/<tid>/` с системным Title ID (до `01000000000010FF`) | предупреждение |
| `atmosphere/exefs_patches/`, `kip_patches/`, `config/`, `hosts/` и прочее в `atmosphere/` | предупреждение |
| файл в корне SD (кроме загрузочных) | предупреждение |
| `bootloader/`, `payloads/`, `emummc/`, `Nintendo/` | запрещено |
| `atmosphere/package3`, `stratosphere.romfs`, `fusee*`, `hbl.nsp`, `kips/`, `exosphere*`, `reboot_payload.bin` | запрещено |
| `.bin`, `.dat`, `.ini`, `.kip`, `.nsp`, `.bmp` в корне SD | запрещено (пейлоады, загрузка) |
| `switch/TorrentShopNX/`, `switch/appstore/.get/` | запрещено |
| `..`, `.`, другие диски, пустой путь | запрещено |

Перед установкой проверяем свободное место (`extracted` из `repo.json`), после скачивания архива — `sha256` (или `md5`). Распаковка идёт через журнал: при отмене и сбое файлы откатываются.

## Учёт установленного

Пишем в формате официального клиента: `sdmc:/switch/appstore/.get/packages/<name>/manifest.install` и `info.json`. Тогда:

- приложения, поставленные через Homebrew App Store, сразу видны у нас как установленные (и наоборот);
- обновления и удаление работают одинаково в обоих клиентах.

Если записи нет, но файл из `binary` есть на карте: «Установлено (версия неизвестна)», кнопка «Обновить» переустанавливает пакет.

## Оверлеи и системные модули

- **Оверлеи** (`.ovl` в `switch/.overlays/`) работают, только если стоят загрузчик оверлеев и меню. При установке первого оверлея предлагаем поставить их вместе с ним, одним окном.
- **Системные модули** (`atmosphere/contents/<tid>/exefs.nsp`):
  - после установки предлагаем «Запустить сейчас» (`pmshellLaunchProgram` по Title ID из пути) или пишем, что заработает после перезагрузки;
  - экран «Системные модули»: список, состояние «работает / выключен» (`pmdmntGetProcessId`), переключатель автозапуска (файл `flags/boot2.flag`);
  - предупреждение: модуль, несовместимый с прошивкой или Atmosphère, может мешать загрузке консоли; выключить его можно здесь же или удалив `boot2.flag` с ПК.

## Экран магазина

- Новой плитки на главном экране нет: там уже 5 плиток по 208 px (1104 из 1280 px), шестая не помещается без уменьшения остальных.
- Плитка «Ретро-игры» становится общим разделом **«Хоумбрю и ретро»** (ключ `app/menu/retro_games` → новый текст во всех языках, новая иконка вместо `img/tile_retro.png`).
- Внутри раздела переключатель **«Хоумбрю | Ретро»** (кнопки LB/RB). Открывается вкладка, на которой пользователь был в прошлый раз (хранится в `config.ini`).
- Вкладка «Ретро» — нынешний `RetroConsolesView` без изменений (Y — эмуляторы, Minus — обновить базы).
- Обновления видны без новой плитки: при фокусе на плитке раздела нижняя панель главного экрана (`DashboardSummaryView`) показывает строку «Хоумбрю: N обновлений» и открывает список по нажатию.
- Вкладки магазина: Все, Игры, Утилиты, Эмуляторы, Оверлеи, Системные модули, Темы, Установленные.
- Сетка с иконками (как каталог игр), поиск, сортировка: популярные (`app_dls`), обновлённые недавно, по имени.
- Карточка: иконка, скриншот, автор, версия (установленная и новая), размер, описание, история изменений, лицензия, ссылка на проект; кнопки «Установить», «Обновить», «Удалить», «Запустить» (для NRO).
- «Установленные»: «Обновить всё» одной кнопкой, по очереди, с общим прогрессом.
- Удаление: стираем файлы по манифесту и пустые папки; настройки из `config/` и файлы с буквой `G` оставляем (с вопросом «Удалить и настройки?»).

## Формат `homebrew.json`

```json
{
 "format": 1,
 "generated": "2026-11-09T06:17:00Z",
 "hidden": ["hekate", "tesla-menu", "owner/repo"],
 "overlay_dependencies": ["nx-ovlloader", "UltrahandOverlay"],
 "fortheusers": { "<имя в repo.json>": { "kinds": ["app", "overlay", "sysmodule"], "description_i18n": { "ru": "..." } } },
 "packages": [{
  "name": "UltrahandOverlay", "title": "Ultrahand Overlay", "author": "ppkantorski", "version": "2.5.4",
  "category": "advanced", "description": "...", "description_i18n": { "ru": "..." }, "changelog": "...",
  "url": "https://github.com/ppkantorski/Ultrahand-Overlay", "repo": "ppkantorski/ultrahand-overlay",
  "updated": "2026-11-08", "download_url": "https://github.com/.../sdout.zip", "download_type": "zip",
  "zip_root": "SdOut/", "sha256": "...", "filesize": 937392, "extracted": 2500000,
  "files": ["U: switch/.overlays/ovlmenu.ovl", "G: config/ultrahand/config.ini"],
  "icon_url": "https://raw.githubusercontent.com/Langegen/switch-game-collection/main/homebrew/icons/UltrahandOverlay.jpg",
  "depends": [], "auto": false, "first_seen": "2026-11-09"
 }]
}
```

- Размеры здесь в байтах (в `repo.json` — в КиБ).
- `download_type: "file"` — один `.nro`/`.ovl`, пишется в `files[0]`.
- `zip_root` — папка-обёртка в архиве GitHub; запись архива = `zip_root` + путь файла.
- Файлы из `config/` у пакетов с GitHub идут с `G`: обновление не затирает настройки.
- Имя пакета, найденного по репозиторию в fortheusers, — имя из fortheusers (общий учёт).
- Сборщик хранит в `homebrew/state.json` кэш: манифесты fortheusers по версиям, разобранные релизы по id файла (повторно не качает), даты появления, проверенные репозитории (повторно — при новом push; без даты push — раз в неделю), автодобавленные репозитории (проверяются каждый прогон, даже если поиск их больше не находит).
- Автодобавление: в релизе ровно один `.nro` или `.ovl` и нет zip, у репозитория ≥ 2 звёзд (`discovery.min_stars`), файл — настоящий NRO. Остальное — в `homebrew/candidates.md` и issue «Кандидаты в магазин хоумбрю».

## Риски

- CDN fortheusers недоступен: работаем по кэшу; в `homebrew.json` можно указать зеркало.
- Описания на английском: для популярных пакетов — свои короткие описания в `homebrew.json`.
- Устаревшие пакеты в магазине (Tesla-menu 2023): заменяем через `homebrew.json`.
- Нагрузка на чужой сервер: `repo.json` не чаще раза в 12 ч и с ETag, свой `User-Agent` `TorrentShopNX/<версия>`.
