## Как работает сейчас

1. `GameDetailView` → кнопка «Автоматическая установка» → `addPortInstall(game_, nullptr, 0)`: плана нет, вариант всегда 0.
2. `portInstallWorker` (`download_manager.cpp`) получает список файлов торрента и вызывает `PortInstallPlanner::analyze`.
3. Архивы распаковываются потоком прямо из торрента в `sdmc:/` (`extractArchiveFromSource`, журнал откатывает только текущий архив).
4. Остальные файлы качаются по путям из `file_destinations`.
5. NSP-ярлык качается в `cache/tmp`, ставится `HybridNspInstaller`, удаляется.

## Пример: Max Payne Mobile (две версии: NX и PCAE)

Инструкция раздачи:

- NX: `maxpaynenx.7z` → корень SD; папку `Homebrew/maxpaynenx` → `sdmc:/maxpaynenx`; ярлыка в раздаче нет.
- PCAE: `PCAE Switch/maxpayne.zip` → `sdmc:/switch/`; из `PCAE Switch/PCAE Switch.zip` папку `maxpayne` → `sdmc:/switch/`; поставить `PCAE Switch/MaxPayne.nsp`.

Что делает текущий планировщик (прогон `analyze` на списке файлов, восстановленном по описанию):

```
game=MaxPayne.nsp  forwarder=MaxPayne.nsp  variants=1 (default)
EXTRACT PCAE Switch/PCAE Switch.zip -> sdmc:/          (нужно sdmc:/switch/, и только папку maxpayne)
EXTRACT PCAE Switch/maxpayne.zip    -> sdmc:/          (нужно sdmc:/switch/)
EXTRACT maxpaynenx.7z               -> sdmc:/          (верно)
Homebrew/maxpaynenx/config.txt      -> sdmc:/switch/MaxPayne.nsp/config.txt   (нужно sdmc:/maxpaynenx/)
```

Итог: качаются обе версии целиком, NX частично на месте (нет файлов из `Homebrew/`), PCAE лежит не там, а ярлык PCAE ставится и указывает на несуществующий `.nro`.

После этапов 1–2 эвристика уже правильно положит `Homebrew/` и не перепутает `PCAE Switch/` с `switch/`. Надёжно эта раздача ставится только через рецепт (этап 3): там «извлечь одну папку из архива в `/switch/`» и «две версии, можно обе».

## Этап 1. Исправления планировщика (без изменений UI)

1. Сегменты пути вместо подстрок: `switch` только как целый сегмент (`^switch/` или `/switch/`); `detectGameFolderName` берёт только папки, имена с расширением отбрасывает.
2. Ключевые слова по токенам имени (разделители: пробел, `_`, `-`, `.`, `()[]`): `rus|russian|ru|рус` / `eng|english|en` / `mod|mods|modded|better pack` / `vanilla|original`. Несколько архивов на вариант.
3. Маркеры корня SD: `Homebrew/`, `sdcard/`, `SD/`, `microSD/`, `SD card/` — содержимое ложится в `sdmc:/` с сохранением структуры (`Homebrew/maxpaynenx/x` → `sdmc:/maxpaynenx/x`). Существующий тест Subway Surfers (`Homebrew/switch/...`) остаётся зелёным.
4. Запасной путь (fallback) сохраняет структуру относительно папки игры; `.txt/.nfo/.url/.md/.jpg/.png` из корня раздачи не копировать.
5. Многотомные архивы: тома группируются в одну задачу (`PortArchiveTask.file_indices`), в отдельные файлы не попадают. `.7z.001`/`.zip.001` распаковываются через источник, склеивающий тома (`ConcatDataSource` поверх `IDataSource`). Многотомный RAR пока сразу отклоняется с понятной ошибкой и советом «Скачать полностью».
6. Безопасность путей: убрать `..` и пустые сегменты в `normalizePath`; запретить запись в `atmosphere/` (кроме `atmosphere/contents/`), `bootloader/`, `Nintendo/`, `emuMMC/` и для файлов, и для содержимого архивов.
7. Вариант по умолчанию: русский только для `ru` (обсудить `uk`/`be`), иначе английский/оригинальный. Воркер при `plan == nullptr` берёт `default_variant_index`.
8. Ярлык привязывается к варианту, если он лежит в папке варианта; при нескольких NSP учитывается размер (ярлык < 50 МБ).
9. Удалить `overlay_file_indices` или задать по нему явный порядок (сначала архивы, потом поверх него отдельные файлы).

Готово, когда: фикстуры этапа 0 дают ожидаемые пути; Max Payne: `Homebrew/` → `sdmc:/maxpaynenx`, имя игры не `MaxPayne.nsp`.

## Этап 2. Заглянуть в архив до скачивания

Оглавление 7z лежит в конце файла (код уже читает его первым), у zip в конце лежит центральный каталог. Значит, список файлов архива можно получить, скачав только хвост.

1. `util::listArchiveFromSource(source, size)` → список путей внутри архива (7z SDK / libarchive по хвосту).
2. Правила выбора, куда распаковывать:
   - в архиве есть `switch/`, `atmosphere/contents/` или другие папки корня SD → распаковывать в `sdmc:/`;
   - в архиве одна папка верхнего уровня с `.nro` внутри → `sdmc:/switch/`;
   - папка верхнего уровня совпадает с именем игры (`maxpayne.zip` → `maxpayne/`) → `sdmc:/switch/`;
   - иначе `sdmc:/switch/<game>/`.
3. Опираться в планировщике на найденный в архиве `.nro`, если он есть.

Готово, когда: PCAE-архивы Max Payne идут в `sdmc:/switch/` без рецепта (при условии, что внутри `maxpayne/…`).

## Этап 3. Рецепты для конкретных раздач

Эвристика не покроет инструкции вида «из архива извлечь только папку X» и «две версии, можно обе». Для таких раздач нужен явный рецепт.

1. Формат JSON по `topic_id`, лежит рядом с каталогом (обновляется вместе с ним) или в romfs:

```json
{
  "topic_id": "…",
  "variants": [
    {"id": "nx", "title_key": "app/ports/variant_original",
     "steps": [
       {"extract": "maxpaynenx.7z", "to": "sdmc:/"},
       {"copy": "Homebrew/maxpaynenx/", "to": "sdmc:/maxpaynenx/"}
     ],
     "launch": "hbmenu"},
    {"id": "pcae", "title_key": "app/ports/variant_mod",
     "steps": [
       {"extract": "PCAE Switch/maxpayne.zip", "to": "sdmc:/switch/"},
       {"extract": "PCAE Switch/PCAE Switch.zip", "subpath": "maxpayne/", "to": "sdmc:/switch/maxpayne/"},
       {"install_nsp": "PCAE Switch/MaxPayne.nsp"}
     ],
     "check": ["sdmc:/switch/maxpayne/maxpayne.nro"]}
  ],
  "combinable": true
}
```

2. Планировщик: есть рецепт → строит план по нему (сверяя имена файлов с торрентом; при несовпадении откатывается к эвристике и пишет в лог); нет рецепта → эвристика.
3. Распаковка одной подпапки из потокового архива: `extractArchiveFromSource(..., pathTransform)` уже умеет переписывать пути, нужен фильтр по префиксу.
4. Десктопный скрипт: прогнать эвристику по всем 268 портам и пометить подозрительные планы (плоский запасной путь, имя игры с расширением, ярлык без `.nro`, больше одного NSP, папки с «версиями»). Рецепты писать для этого списка.

Готово, когда: Max Payne ставится в любой из версий и в обе сразу.

## Этап 4. Интерфейс выбора и предпросмотра

1. По кнопке «Автоматическая установка»: `probeTorrentFiles` с экраном ожидания (`auto_install_probing`), ошибки `auto_install_probe_failed` / `auto_install_not_port`.
2. Если вариантов больше одного, диалог `choose_version_title` с размерами и пунктом «Обе версии» (если `combinable`). План и вариант передаются в `addPortInstall`, размер в очереди сразу верный.
3. Экран «что куда ляжет»: папки назначения, ставится ли ярлык, сколько нужно места и сколько свободно.
4. Итог: «Ярлык установлен» или «Ярлыка в раздаче нет — запускайте из hbmenu (Альбом)».

## Этап 5. Надёжность воркера

1. Свободное место: распакованный размер (из оглавления архива) + NSP + кэш движка; проверка до старта и перед каждым архивом.
2. Один журнал на всю установку: при ошибке или отмене откатываются все этапы, не только текущий архив.
3. Повтор пропускает завершённые этапы (отметки этапов в элементе очереди; распакованные архивы проверяются по журналу).
4. Отмена без блокировки UI: выставить флаг, закрыть источник, а future отдать фоновому «уборщику» вне `queue_mutex_`.
5. Пауза во время установки NSP; удаление временного NSP на всех путях выхода.
6. Проверка после установки: файлы из `check` рецепта или хотя бы один `.nro` в `sdmc:/switch/<game>/`.
7. Убрать фолбэк `total_files = 256` и обращение `files[idx]` по позиции: искать по `files[i].index`.

## Этап 7. Учёт установленных портов

1. После успешной установки писать манифест в `TSNX_DATA_DIR/ports/<topic_id>.json`: версия раздачи, вариант, список записанных файлов и папок, title ID ярлыка.

3. Обновление удаляет файлы, которых нет в новой версии; удаление стирает файлы по манифесту и удаляет ярлык через NCM.
